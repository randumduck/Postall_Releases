3. How to Generate a Signed License Key

1. Navigate to the License Forge UI in your browser at http://localhost:8081.

2. Fill in the Client / Organization Name (e.g., Acme Cyber Defense Corp).

3. Select your target Tier Preset:

- Creator Tier (₹999/mo)

- Professional Tier (₹4,999/mo)

- Sovereign Enterprise Tier (₹19,999+/mo)

4. Set Validity Period (e.g., 30, 90, 365 days).

5. *(Optional)* Provide a Hardware ID (HWID) to cryptographically lock the key to a specific physical server node.

6. Click Generate Signed License Key.

7. Copy the generated Base64 license key string.

CLI Alternative via curl:


curl -X POST "http://localhost:8081/api/licenses/generate" \
  -H "Content-Type: application/json" \
  -d '{
    "client_name": "Acme Cyber Defense Corp",
    "tier": "enterprise",
    "duration_days": 365
  }'

4. How to Activate the License in Postall Engine

1. Open the Postall Command Center at http://localhost:8000.

2. In the left navigation menu, click Admin & Governance -> System Configuration.

3. Scroll to the Cryptographic License Management section.

4. Paste the Base64 key into the Enter License Key input field.

5. Click Verify & Activate License.

6. The dashboard will verify the Ed25519 signature against the embedded public key, immediately updating your entitlements badge.

POSTALL HOW-TO GUIDE: 02

Sovereign Local AI Cockpit & 100% Control Panel

Subsystem: Local Offline AI Engine

Node: postall_llm (http://localhost:11434)

1. Overview

Postall gives operators and enterprise buyers 100% control over the sovereign local artificial intelligence engine. No data leaves the physical server. The Sovereign Local AI Cockpit allows full customization of inference parameters, model selection, prompt personas, and live latency benchmarking.

2. Hyperparameter Controls

The following controls can be tuned in real-time under Settings -> AI & Models -> Sovereign Local AI Cockpit:

1. Installed Model Selector: Dynamically queries available models from postall_llm (e.g. postall_ai:latest, qwen2.5:1.5b, llama3.2:3b).

2. Temperature (0.0 to 1.0):

- 0.2 - 0.4: Strict analytical facts, compliance reports, and incident runbooks.

- 0.7: Recommended default for strategic thought-leadership posts.

- 0.9: Creative brainstorming and marketing hooks.

3. Top-P Sampling (0.1 to 1.0): Nucleus sampling threshold.

4. Context Window (num_ctx):

- 2,048 Tokens: High-throughput burst mode.

- 4,096 Tokens: Recommended balanced operating point.

- 8,192 Tokens: Deep syllabus document and architecture analysis.

- 16,384 Tokens: Full multi-chapter curriculum ingestion.

5. CPU Thread Allocation (num_threads): Configure the number of physical CPU cores dedicated to inference (1 to 16 cores).

6. Custom System Persona Prompt: Global system instructions passed directly into the local model.

3. How to Run a Live Latency Benchmark

To attest performance to investors or buyers:

1. Open System Configuration -> Sovereign Local AI Cockpit.

2. Click ⚡ Run Latency Benchmark.

3. Postall will send a standardized 50-token test prompt to the local engine.

4. The dashboard displays real-time telemetry:

- Inference Latency: e.g., 48.2 ms

- Generation Speed: e.g., 32.4 tok/s

- Airgap Verification: 100% Verified (0 Bytes Egress)

API Command:


curl -X POST "http://localhost:8000/api/local-ai/benchmark" \
  -H "Authorization: Bearer <TOKEN>"

Public Cloud AI Integration & Multi-AI Failover Pool

Subsystem: Hybrid Cloud Intelligence Router

Supported Providers: Google Gemini, Mistral AI, OpenAI, Anthropic Claude, Perplexity

1. Overview

Postall operates primarily in Sovereign Local AI mode. When enterprise policies permit cloud connectivity, operators can enable BYO-Key (Bring Your Own Key) public AI providers for high-speed fallback and specialized multimodal reasoning.

2. Configuring Google Gemini

1. Obtain an API key from Google AI Studio (aistudio.google.com).

2. Open Postall Dashboard -> Settings -> AI & Models.

3. Under Google Gemini (BYO-Key):

- Paste your API Key into the field.

- Select your preferred model: gemini-2.0-flash (recommended for ultra-fast synthesis) or gemini-1.5-pro (deep reasoning).

4. Click Save Settings.

5. Click Test API Key to verify the handshake.

3. Configuring Mistral AI

1. Obtain an API key from Mistral Console (console.mistral.ai).

2. In Settings -> Mistral AI (BYO-Key), enter your API key.

3. Select mistral-large-latest or codestral-latest.

4. Click Save Settings.

4. Multi-AI Failover Pool

When Autonomous AI Failover Pool is toggled ON (available on Professional & Sovereign Enterprise tiers):

  • If the primary provider encounters HTTP 429 (rate-limit) or a transient outage, Postall automatically routes the prompt to the next healthy provider in the round-robin pool.
  • If all public APIs fail or network egress is blocked, Postall transparently fails over to the **Local Offline AI engine** with zero post interruption.

    Subsystem: Network Mesh & Production Operations

    1. Deployment Topology

    Postall is deployed as an air-gapped Docker container cluster communicating over the internal bridge network postall_mesh:

    
# 1. Create Postall Mesh Network
docker network create postall_mesh

# 2. Deploy License Forge
docker run -d --name postall_license_forge --network postall_mesh \
  -p 8081:8001 randumduck69/postall_license_forge:latest

# 3. Deploy Local Sovereign LLM
docker run -d --name postall_llm --network postall_mesh \
  -p 11434:11434 randumduck69/postall_ai:latest

# 4. Deploy Zero-Trust Gateway
docker run -d --name postall_gateway --network postall_mesh \
  -p 8080:8080 randumduck69/postall_gateway:latest

# 5. Deploy Postall Core Engine
docker run -d --name postall_engine --network postall_mesh \
  -p 8000:8000 -v postall_data:/app/data randumduck69/postall:latest

    2. Zero-Trust Gateway Security Features

  • **Token-Bucket Rate Limiting:** Enforces maximum request thresholds per IP/Actor to prevent denial-of-service.
  • **Anti-Replay JTI Validation:** Ephemeral tokens contain cryptographic unique JWT IDs (`jti`) tracked with TTL.
  • **Strict Headers:** CSP, HSTS, X-Content-Type-Options, X-Frame-Options enabled on all responses.

  • **Hybrid Domain Memory (Fine-Tuning + RAG):** Ingests domain guidelines into both the model system persona and the local SQLite memory vector table (`local_llm_memory`) with strict workspace isolation.
